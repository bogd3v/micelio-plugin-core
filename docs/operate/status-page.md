# Status page

The **Micelio** entry of the admin's menu, marked with the Micelio icon, opens the Micelio section, whose first page is the status page: the operator's first view of an installation, what runs, what is reachable and what failed. It changes no content: besides reading, it can only run the host check again. It is in English and Spanish, as the admin is.

## Who sees it

A role with the permission **Read the Micelio status page** (`plugin::micelio.status.read`, in Settings → Roles → Plugins → Micelio). The super admin has it; the Editor and Author roles do not, since the page shows the host's configuration. Give it to another role there.

The menu entry itself needs no permission: any admin user sees it. A role without the status permission does not see **Status** in the sub-navigation and lands on **About Micelio**, which shows no configuration ([about-page.md](about-page.md)); the pages of sibling plugins show to the roles that have their permission.

**Not available** is not a failure. The frontend's health endpoint arrives with bogd3v/micelio#702; until a frontend serves it, or while it is down, the page says it did not answer. The page asks every frontend again each time it loads, at most two seconds each.

The checks of the plugins never run when the page loads: they run with **Run host check** and once a day (`statusRefreshRule`, [README](../../README.md#configuration)). **Copy diagnostics**, at the end of the page, copies a few lines for a support request: the versions, whether the host check passes and one line per plugin with how many of its checks are ok, warn or failing. It copies no finding, site name or address.

A sub-navigation on the left lists the Micelio pages in groups (Installation, Content, Site; **About Micelio** has no heading and sits under a divider, and the open item has a bar on its right edge); a group with no page the user may see is left out. The group ids that sibling plugins register into (`overview`, `content`, `site`) keep their values: only the label of `overview` reads Installation. Sibling plugins add pages to the first three ([extension points](../plugins/extension-points.md)). The status page keeps its address, `/admin/plugins/micelio`.

The host check runs when Strapi starts, before the frontends are usually up. **Run host check**, in the page header, runs it now (one run at a time): use it after fixing a failure, or once the frontends are up. It never stops Strapi, even in production when a required check fails; restarting does. Without access to the page, `npx micelio doctor` in the Strapi project's folder runs the same checks.

The data comes from `GET /micelio/status` ([docs/api.md](../api.md#status)).
